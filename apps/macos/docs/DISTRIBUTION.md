# Distributing the Cue macOS app

> **Default auth:** notarization uses the App Store Connect API key already on this Mac (`~/.appstoreconnect/private_keys/AuthKey_753495X7A6.p8`) — no Apple ID or app-specific password needed. The env vars below are the FALLBACK path only.


How to ship signed, notarized, auto-updating builds of `apps/macos` beyond
the founder's machine. Local unsigned dev packs (`bun run pack`) keep working
without any of this — every step below no-ops with a logged message when its
credentials are absent.

## How the pieces fit

- **Signing** — electron-builder signs the app with your `Developer ID
  Application` certificate (found automatically in the login keychain), with
  hardened runtime + the entitlements in `scripts/entitlements/`. The
  `scripts/afterSign.js` hook then re-signs the bundled `bun` and
  `vellum-mac-helper.app` with their own entitlements and re-seals the outer
  app.
- **Notarization** — `scripts/notarize.cjs` (chained at the end of
  `afterSign.js`, after the re-seal) submits the app to Apple's notary
  service via `notarytool` and staples the ticket. Driven by `APPLE_ID`,
  `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID` (defaults to `XU8BLQACGU`).
  Skipped with a clear log when creds are missing or the build isn't
  Developer-ID signed.
- **Auto-update** — electron-updater against **GitHub Releases on a public
  releases-only repo** (`manav1125/cue-releases` by default). The source repo
  is private, and electron-updater can only read private release assets with
  a runtime token — unacceptable for distributed builds — so releases live in
  a separate public repo that holds only artifacts, no code. electron-builder
  bakes the feed into the app (`app-update.yml`); packaged `production`/
  `local` builds check on launch and every 4 hours, plus the app-menu
  "Check for Updates…" item. Overrides: `CUE_UPDATE_FEED_URL` (generic feed),
  `CUE_AUTO_UPDATE=0` (kill switch), `CUE_RELEASES_OWNER`/`CUE_RELEASES_REPO`
  (build-time repo override).

## One-time setup

### 1. Developer ID Application certificate

Needs a paid Apple Developer account on team `XU8BLQACGU` (same team as the
iOS app).

1. Xcode → Settings → Accounts → select the team → *Manage Certificates…* →
   **+** → *Developer ID Application*. (Or: developer.apple.com →
   Certificates → create *Developer ID Application* from a CSR generated by
   Keychain Access.)
2. Verify it's in the login keychain:

   ```sh
   security find-identity -v -p codesigning
   # expect: "Developer ID Application: <name> (XU8BLQACGU)"
   ```

   electron-builder autodiscovers it — no config needed. To pin an identity
   explicitly, set `CSC_NAME="Developer ID Application: <name> (XU8BLQACGU)"`.
3. **Back it up**: Keychain Access → export the certificate + private key as
   a password-protected `.p12`. Losing the private key means re-issuing the
   cert (and CI needs the `.p12` as `CSC_LINK`/`CSC_KEY_PASSWORD`).

### 2. Notarization credentials

1. appleid.apple.com → Sign-In and Security → **App-Specific Passwords** →
   generate one (e.g. "cue-notarize").
2. Export for release shells (or put in a `.env` you source — never commit):

   ```sh
   export APPLE_ID="<apple-id email on team XU8BLQACGU>"
   export APPLE_APP_SPECIFIC_PASSWORD=<the app-specific password from appleid.apple.com>
   export APPLE_TEAM_ID="XU8BLQACGU"   # optional — this is the default
   ```

### 3. Releases repo + token

1. Create a **public** repo `manav1125/cue-releases` (empty; artifacts only).
   If you pick another name, build with `CUE_RELEASES_OWNER`/
   `CUE_RELEASES_REPO` set so the baked feed matches.
2. Create a GitHub token with `repo` scope on that repo (fine-grained:
   *Contents: read & write*) and export it:

   ```sh
   export GH_TOKEN="ghp_…"
   ```

## Cutting a release

```sh
cd apps/macos

# 1. Bump the version — electron-updater compares semver, so this IS the release id.
#    Edit package.json "version" (e.g. 0.0.1 → 0.0.2).

# 2. Build, sign, notarize, publish (env vars from one-time setup exported):
bun run pack -- --environment production --publish

# 3. Publish the GitHub release: electron-builder uploads a DRAFT release
#    (v<version>) with Cue-<version>-arm64.dmg, Cue-<version>-arm64-mac.zip,
#    and latest-mac.yml. Review it on github.com/manav1125/cue-releases and
#    click "Publish release" — the feed is live the moment it's published.
```

Notes:

- Do **not** set `CSC_IDENTITY_AUTODISCOVERY=false` for release builds — that
  is the switch for unsigned local packs.
- Notarization typically takes 2–10 minutes; the pack blocks on it.
- `x64` build: repeat with `ELECTRON_TARGET_ARCH=x64` and publish into the
  same draft release before publishing it.
- Existing installs pick the release up on next launch (or within 4 hours,
  or via app menu → "Check for Updates…"), download in the background, and
  install on quit. Updates only install over a signed app — unsigned local
  packs will log an error at install time, which is expected.

### Verifying a release build

```sh
APP="dist/mac-arm64/Cue.app"   # or the newest dist/mac*/ dir
codesign --verify --deep --strict --verbose=2 "$APP"
spctl -a -vv -t exec "$APP"            # expect: accepted, Notarized Developer ID
xcrun stapler validate "$APP"
```

## CI later

The same flow works headless: provide `CSC_LINK` (base64 `.p12`) +
`CSC_KEY_PASSWORD` instead of the keychain cert, plus the same
`APPLE_ID`/`APPLE_APP_SPECIFIC_PASSWORD`/`APPLE_TEAM_ID`/`GH_TOKEN` secrets,
and run the identical `pack.sh --environment production --publish`.
