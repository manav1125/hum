# Cue — Deploy (single-tenant)

Self-hosted Cue on **Render** (Tier A from `CUE-INFRA-SPEC.md`). One private Cue
for you/your team; the multi-tenant k8s tier is a later evolution, and nothing
here blocks it.

## Topology

```
                 public (TLS)
                      │
              ┌───────▼────────┐
              │  cue-gateway   │  :7830   only public ingress
              │  (web service) │          webhooks · OAuth callbacks · client API
              └───────┬────────┘
        private network (service-name DNS)
        ┌─────────────┼───────────────┐
┌───────▼──────┐ ┌────▼──────┐ ┌───────▼───────┐
│ cue-assistant│ │  cue-ces  │ │  cue-qdrant   │
│   :3001      │ │  :8090    │ │   :6333       │
│ brain+memory │ │ secrets,  │ │ vector store  │
│ disk:/workspc│ │ isolated  │ │ disk:storage  │
└──────────────┘ │ disk:     │ └───────────────┘
                 │/ces-security│
                 └───────────┘
```

`egress-proxy` is **not** a separate service — it ships in-process inside CES.
Auth: gateway↔assistant via `ASSISTANT_API_KEY`; assistant↔CES via
`CES_SERVICE_TOKEN`; gateway signs client sessions with `GATEWAY_JWT`. All three
are auto-generated and shared by the `cue-shared-tokens` env group.

## Clients (all talk to the gateway URL)

| Client | Distribution | Notes |
| --- | --- | --- |
| **Web** (`apps/web`) | Render Static Site (build→CDN) or served by gateway | point API base at the gateway domain |
| **Desktop** (`apps/macos`) | electron-builder → sign+notarize → release bucket → `electron-updater` auto-update | repoint the GCS URL in `apps/macos` to your bucket (Cloudflare R2 recommended) |
| **iOS** (`apps/macos`/Capacitor, `release-ios.yaml`) | Xcode archive → TestFlight → App Store | Apple pipeline; gateway is the API target |

## First deploy

1. **Local parity (recommended sanity check first):**
   ```sh
   cp deploy/.env.cue.example deploy/.env.cue   # fill in; generate tokens with: openssl rand -hex 32
   docker compose --env-file deploy/.env.cue -f deploy/docker-compose.yml up --build
   ```
   Hit `http://localhost:7830/healthz`.

2. **Render Blueprint:** connect this repo in Render → New → Blueprint → it reads
   `render.yaml`. Render auto-generates the shared tokens and provisions the
   disks. Then in the dashboard set the `cue-secrets` values (see below).

3. **Domain + TLS:** add a custom domain to `cue-gateway` (Render issues TLS).
   Point the web/desktop/iOS clients at `https://<that-domain>`.

4. **Smoke test:** `GET https://<domain>/healthz` and `/readyz`; create a
   conversation from a client.

## Secrets you set yourself (Render dashboard → env groups)

Auto-generated by Render (no action): `CES_SERVICE_TOKEN`, `ASSISTANT_API_KEY`,
`GATEWAY_JWT`.

You provide (`cue-secrets`, `sync: false`):

- `ANTHROPIC_API_KEY` — the brain runs on **Fable 5** (`claude-fable-5`).
- `TELEGRAM_BOT_TOKEN` / `TELEGRAM_WEBHOOK_SECRET` — only if using Telegram.
- OAuth client secrets (Google, etc.), Twilio/voice, Composio — add as you wire
  each channel; the gateway holds inbound, CES holds the credentialed calls.

**Do not paste live secrets into chat or commit them.** Enter values directly in
Render's UI. `deploy/.env.cue` is gitignored.

## Open items to validate at deploy time

- **Sandboxing:** the assistant uses bubblewrap / apt-chroot for sandboxed skill
  + bash execution. Render's container platform may not grant the required user
  namespaces; the daemon boots in **degraded mode** (sandboxing off, everything
  else works) if so. If sandboxed execution is required, that's the signal to
  move the assistant to the k8s/kata tier.
- **Disk = single instance:** Render pins a service with a disk to one instance
  (correct for single-tenant; revisit for HA/multi-tenant).
- **CES one-disk:** Render allows one disk per service, so CES data lives under
  `/ces-security/data` on the security disk. Confirm CES writes there.
- **Block-volume scripts** (`vellum-block-volume-*`) in the images are
  GCP-specific; on Render the disk is mounted directly — they should no-op.
- **CES managed API port:** assumed `8090` (the only exposed port). Confirm the
  credential API + health share it.
